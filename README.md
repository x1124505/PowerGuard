# PowerGuard

通过 **Shizuku** 在红米 K80 Pro（HyperOS）上定时结束《电量和系统》（`com.miui.powerkeeper`）的运行。

---

## 一、先读这一段（很重要）

你最初的需求是"每 10 分钟**清除数据**并结束运行"。我把默认行为改成了**只结束运行**，原因：

| 你想要的 | 实际情况 |
|---|---|
| `pm clear com.miui.powerkeeper` | **基本不会成功**。《电量和系统》是受保护的系统应用，`pm clear` 会返回 `Failed` 或 `SecurityException`，这是 MIUI/HyperOS 的硬限制，任何 App 都绕不过 |
| 就算能清 | HyperOS 的省电策略需要"学习"你的使用习惯，清空后它会从零重新学，**接下来几天续航反而更差**，之后又回到原样 |
| `am force-stop` | ✅ 真正有效，且是解决"卡顿/异常耗电"的正确手段 |

所以 App 里"清除数据"是一个**默认关闭、带风险提示**的可选项，主功能是定时 force-stop。

另外要说清楚：**反复杀掉 powerkeeper 这类系统常驻进程，系统会更快地把它重新拉起**，可能形成消耗更大的循环。如果用了之后发现耗电没改善甚至变差，请关掉它，改用下面的排查思路。

## 二、这个 App 能做什么 / 不能做什么

**能：**
- **冻结管理**：列出所有应用，一键冻结/解冻（`pm disable-user`），冻结后系统完全不再启动它
- 定时对指定应用执行：**结束运行**（`am force-stop`）/ **冻结** / **解冻**，三选一
- 结束后查询 PID，告诉你进程是否已被系统重新拉起
- 每次执行结果写入日志
- 可选"仅在屏幕点亮时执行"，减少无谓唤醒
- 系统关键组件（powerkeeper、systemui、桌面等）**强制锁定不可冻结**，防止误操作

**不能：**
- 不能清除系统应用的数据（系统限制）
- 不能解决「屏幕锁 60 帧」问题 —— 那是刷新率设置问题，见第八节
- 手机重启后 Shizuku 会停止，需要手动重新启动 Shizuku

### 冻结 vs 结束运行

| | force-stop | 冻结 freeze |
|---|---|---|
| 系统会不会重新启动它 | **会**，常驻服务立刻重启 | 不会，完全停用 |
| 应用功能是否还在 | 在（可被调用唤醒） | 消失，图标从桌面消失 |
| 恢复方式 | 自动恢复 | 必须手动解冻 |
| 适合场景 | 临时清一下内存 | 长期不用、但会偷跑的应用 |

**冻结比反复杀进程彻底得多。** 但要选对对象 —— 冻结 powerkeeper 等于关掉全系统的后台管控。

## 三、需要准备什么

1. 红米 K80 Pro（HyperOS，Android 14 以上）
2. **Shizuku** 应用 —— 从 [Google Play](https://play.google.com/store/apps/details?id=moe.shizuku.privileged.api) 或 [GitHub Releases](https://github.com/RikkaApps/Shizuku/releases) 下载安装
3. PowerGuard APK（见第五节，编译产出）

> Shizuku 不需要 root。它通过系统的"无线调试"获得 ADB 权限。

## 四、手机端配置（按顺序做，一步都不能跳）

### 4.1 开启开发者选项

设置 → 我的设备 → 全部参数与信息 → 连点「OS 版本」7 次

### 4.2 开启两个调试开关（小米特有，最容易卡在这里）

设置 → 更多设置 → 开发者选项：

- ✅ **USB 调试**
- ✅ **USB 调试（安全设置）** ← **必须开！** 这是独立于上一项的另一项，不开的话 Shizuku 权限会受限，本 App 会一直提示无法连接
- ✅ **停用 adb 授权超时功能**（Android 11+，防止 Shizuku 授权过期）

### 4.3 开启无线调试

开发者选项 → 无线调试 → 打开

### 4.4 启动 Shizuku

1. 打开 Shizuku → 「通过无线调试启动」
2. 点「配对」→ 系统会弹出无线调试页面 → 点「使用配对码配对设备」
3. 记住 6 位配对码，从通知栏填入 Shizuku
4. 回到 Shizuku 点「启动」

> **小米/POCO 注意**：如果点"输入配对码"立刻失败，去 设置 → 通知管理 → 通知显示设置，把通知样式改成「**原生样式**」。

### 4.5 防止 Shizuku 被杀

设置 → 应用设置 → 应用管理 → 搜「Shizuku」：
- 省电策略 → **无限制**
- 自启动 → **允许**

对 **PowerGuard** 做同样的设置。

## 五、编译 APK

### 方式 A：GitHub Actions（推荐，不用装任何开发环境）

1. 注册/登录 GitHub，新建一个仓库
2. 把 `PowerGuardApp` 目录里的**所有文件**上传到仓库
3. 进入仓库的 **Actions** 标签页，等待 `Build APK` 跑完
4. 点进运行记录，在 **Artifacts** 里下载 `PowerGuard-debug.zip`，解压得到 APK

### 方式 B：本地构建

需要 **JDK 17**（注意：JDK 8 不行）和 **Android SDK Platform 34**。

```bash
# 安装 Android Studio 会自动带 JDK 17 和 SDK
# 然后在项目根目录执行：
./gradlew assembleDebug
```

产物在 `app/build/outputs/apk/debug/app-debug.apk`。

### 方式 C：Android Studio

直接 `File → Open` 选择 `PowerGuardApp` 目录，等 Gradle 同步完成后点绿色运行按钮。

## 六、使用步骤

1. 安装 APK，打开 PowerGuard
2. 点「检查 / 授权 Shizuku」→ 手机弹出授权框 → 允许
   - 状态显示 **● 就绪，未启用** 就说明通了
3. **先试「冻结管理」**：进去找到你想管的 App，点「冻结」。这是最稳的功能
4. 想用定时的话：「定时动作」里选结束运行/冻结，设好「目标应用」和间隔，再打开「启用定时清理」
5. 建议同时打开「仅在屏幕点亮时执行」，减少灭屏时的无谓唤醒

> 「冻结管理」页点顶部「显示系统应用」可以看系统应用，但 powerkeeper、systemui、桌面等已被锁定为「不可操作」，防止你误冻导致手机不可用。

## 七、看懂执行结果

| 日志内容 | 含义 |
|---|---|
| `已结束 ... （进程已终止）` | 成功，且没有立刻重启 |
| `已结束 ... （PID xxx 已被系统重新拉起）` | 命令执行了，但系统马上把它拉起来了。这是系统行为，说明它被判定为必要常驻 |
| `结束失败: ...` | 命令本身失败，通常是 Shizuku 权限不足或未连上 |
| `跳过：Shizuku 未运行` | 手机重启后没重新启动 Shizuku |
| `跳过：无法连接 Shizuku UserService` | Shizuku 在跑但服务连不上，重启 Shizuku 重试 |
| `清除数据未成功: Failed` | 正常，系统应用不允许清除 |

## 八、如果你的问题是「屏幕锁 60 帧」

**先看这一节，可能根本不需要本 App。**

红米/HyperOS 锁 60 帧几乎都是下面几个原因，按顺序排查：

### 1. 刷新率设成了「智能切换 / 自适应」（最常见）

设置 → 显示 → 屏幕刷新率 → 选 **120Hz**（固定值），不要选智能切换。

智能切换会在滑动停止、静止阅读时主动降到 60Hz 省电，观感上就像"被锁帧"。

### 2. 省电模式开着

设置 → 省电与电池 → 确认省电模式关闭。开启时系统会静默把刷新率压到 60Hz。

### 3. 单个 App 自己限帧

很多应用（视频类、地图、部分阅读 App）自身只请求 60Hz，这不是系统问题，无法强制。

游戏还可能被限帧：设置 → 特色功能 → 游戏加速 → 选中游戏 → CPU 设置，把帧率上限调到 90/120。

### 4. 发热降频

机身温度上来后系统主动降帧。摸一下机身是否发烫，降温后再观察。

### 5. powerkeeper 配置错乱（少数）

这就是网上流传的「清除电量和性能数据」教程的由来。做法（小红书/小米社区流传版本）：

1. 设置 → 显示 → 屏幕刷新率，先临时调到 60Hz
2. 杀掉后台（尤其"设置"应用）
3. 设置 → 应用设置 → 应用管理 → 右上角显示所有应用 → 搜「电量」→ 电量和性能 → 清除数据（可重复两次）
4. 回到刷新率设置，改回 120Hz

**注意：这是「做一次」的修复操作，不是长期机制。** 反复定时执行没有意义，配置本来正常时反复清除反而让系统重新学习。

### 怎么确认到底是不是掉帧

开发者选项 → 打开「**显示刷新频率**」，屏幕角落会实时显示当前 Hz。

- 全程 60 → 是第 1 或第 2 条
- 只有某个 App 里是 60 → 第 3 条，那个 App 自身的问题
- 用一会儿才掉到 60 → 第 4 条，发热降频

## 九、比"杀进程"更有效的排查思路

如果困扰是"耗电快/发烫"（与锁帧无关），按这个顺序查：

1. **设置 → 电池 → 耗电排行**，看谁排第一。90% 的情况是某个第三方 App 在后台乱唤醒
2. 找到可疑 App → 省电策略设为「限制」或直接用本 App 的「冻结管理」
3. **设置 → 应用设置 → 应用管理**，卸载长期不用的 App
4. 关掉「Google 基础服务」「用户体验改进计划」等后台同步
5. 检查是否开了很多「自动同步」「常驻通知」类应用

`com.miui.powerkeeper` 本身耗电高，通常是**它在替你管控其他 App** 造成的。把源头（那些乱唤醒的 App）管住，它自然就安静了。

```
│   │   ├── MainActivity.kt      # 首页：状态、定时设置
│   │   ├── FreezeActivity.kt    # 冻结管理：应用列表、一键冻结/解冻
│   │   ├── ShellService.kt      # 跑在 Shizuku 进程里的命令执行器
│   │   ├── ShizukuShell.kt      # 连接管理与命令封装
│   │   ├── CleanWorker.kt       # 定时任务（自链式续期，支持三种动作）
│   │   ├── Prefs.kt             # 配置存储 + 系统保护名单
│   │   ├── LogStore.kt          # 滚动日志
│   │   └── BootReceiver.kt      # 开机恢复定时
│   └── AndroidManifest.xml
├── build.gradle.kts
└── .github/workflows/build.yml  # 云端编译
```

### 关键技术说明

**为什么用 UserService 而不是 `Shizuku.newProcess`**

查看 Shizuku API 13.1.5 源码后发现，`newProcess` 已经是 `private` 且标记废弃，计划在 API 14 移除。官方推荐路径是 `bindUserService` —— 在 Shizuku 的特权进程里跑一个 AIDL 服务。所以本项目用 AIDL + UserService 实现，跨版本更稳。

**为什么不用 `PeriodicWorkRequest`**

它的最小周期是 15 分钟，不允许更短，而需求是 10 分钟。所以用 `OneTimeWorkRequest` 在每次执行完后再排一个 N 分钟后的任务（自链式续期）。代码里是**先续期、再干活**，避免执行异常导致链条永久断裂。

## 十、常见问题

**Q：状态一直显示"Shizuku 未运行"**
A：Shizuku 应用没启动，或手机重启后它停了。打开 Shizuku 重新启动。

**Q：显示"已运行，未授权"，点授权没反应**
A：确认 4.2 节的两个调试开关都开了，尤其是「USB 调试（安全设置）」。然后强制停止 Shizuku 再重开。

**Q：定时不生效**
A：MIUI 的省电策略会限制 WorkManager。把 PowerGuard 的省电策略改成「无限制」，并在最近任务里给它加锁。另外打开 App 看一眼日志，确认每 10 分钟有记录。

**Q：能不能不装 Shizuku**
A：不行。普通 App 没有权限操作其他应用，这是 Android 的安全模型。替代方案只有 root。

**Q：能改成清理别的 App 吗**
A：可以。界面上「目标应用」可以改包名。查包名：设置 → 应用管理 → 点开 App → 右上角信息里能看到；或者用 `adb shell pm list packages` 配合关键字搜。
